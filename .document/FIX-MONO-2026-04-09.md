# 修复单体部署认证问题 - 2026-04-09

## 问题描述

在单体部署模式下，论坛模块调用管理员接口时仍出现 `PermissionDeniedException: 无效的认证信息` 错误。

错误日志显示：
```
at dev.saraki.wofuf.modules.users.infra.auth.springSecurity.JwtUserAuthenticationTokenFilter.doFilterInternal
```

## 根本原因

单体部署时，用户模块和论坛模块在同一个应用中运行，导致：
1. 用户模块的 `JwtUserAuthenticationTokenFilter` 被加载
2. 该 filter 创建的是标准 `UsernamePasswordAuthenticationToken`，没有 `details` 属性
3. `PermissionAspect` 无法从 `authentication.details` 获取 `JwtTokenInfo`

## 解决方案

更新 `PermissionAspect`，使其支持两种认证方式：

### 方式 1: 分布式部署（从 details 获取）

```kotlin
val tokenInfo = authentication.details as? JwtTokenInfo
val userId = tokenInfo.userId
val isAdminUser = tokenInfo.isAdminUser
```

### 方式 2: 单体部署（从 authorities 获取）

```kotlin
val userId = authentication.principal.toString()
val isAdminUser = authentication.authorities.any {
    it.authority == "ROLE_ADMIN"
}
```

## 修改文件

**modules-forum/infra/aop/PermissionAspect.kt**

添加了两个辅助方法：

1. `getUserId(authentication: Authentication): String`
   - 优先从 `JwtTokenInfo` 获取 userId
   - 否则从 `principal` 获取

2. `isAdmin(authentication: Authentication): Boolean`
   - 优先从 `JwtTokenInfo` 获取 isAdminUser
   - 否则从 `authorities` 判断是否有 `ROLE_ADMIN`

## 代码示例

```kotlin
/**
 * 获取当前用户 ID
 */
private fun getUserId(authentication: Authentication): String {
    // 方式 1: 从 JwtTokenInfo 获取
    val tokenInfo = authentication.details as? JwtTokenInfo
    if (tokenInfo != null) {
        return tokenInfo.userId
    }

    // 方式 2: 从 principal 获取
    return authentication.principal.toString()
}

/**
 * 检查是否为管理员
 */
private fun isAdmin(authentication: Authentication): Boolean {
    // 方式 1: 从 JwtTokenInfo 获取
    val tokenInfo = authentication.details as? JwtTokenInfo
    if (tokenInfo != null) {
        return tokenInfo.isAdminUser
    }

    // 方式 2: 从 authorities 获取
    return authentication.authorities.any {
        it.authority == "ROLE_ADMIN"
    }
}
```

## JWT Token 格式

用户模块签发的 JWT Token 包含以下声明：

```json
{
  "sub": "YaeSaraki",
  "uid": "user-id-here",
  "jti": "session-id-here",
  "ver": "0",
  "admin": true,
  "iat": 1680900000,
  "exp": 1680903600
}
```

- `sub`: 用户名
- `uid`: 用户 ID
- `jti`: 会话 ID
- `ver`: Token 版本
- `admin`: 是否为管理员
- `iat`: 签发时间
- `exp`: 过期时间

## 权限检查流程

```
1. 检查用户是否已登录
   ↓
2. 获取用户 ID（从 details 或 principal）
   ↓
3. 检查是否为管理员（从 details 或 authorities）
   ├─ 是管理员 → 允许访问
   └─ 不是管理员 → 继续
   ↓
4. 查询本地 Member 数据库
   ↓
5. 检查是否有对应权限点
   ├─ 有权限 → 允许访问
   └─ 无权限 → 拒绝访问
```

## 注意事项

1. **单体部署**：用户模块 filter 先执行，设置 `ROLE_ADMIN` authority
2. **分布式部署**：共享 filter 先执行，设置 `JwtTokenInfo` details
3. **兼容性**：新代码同时支持两种部署模式
4. **向后兼容**：不影响现有的分布式部署方案
